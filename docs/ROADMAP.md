# 남은 작업과 검증 순서

## 1 실제 연결 승인 후 검증

- [ ] 사용자 LAW_OC로 법령 검색·전문·부칙·판례 전문 호출. IP/접근 권한은 공식 계정에서 확인.
- [ ] Windows LG Gram에서 설치, 파일 업로드, Word 저장, 한글 경로 확인.
- [ ] 실제 Ollama 모델별 지연시간, JSON 출력 실패율, 인용 탈락률 측정.
- [ ] 임베딩 선택 전/후 한국어 법률 검색 평가. 현재 RRF 점수는 확률이 아님.
- [ ] ego(lite) 공식 CLI 가이드에 맞는 로컬 연결 검증. 현재는 수동 탐색 요청 전달 방식.
- [ ] GitHub 저장소의 존재·권한 확인 후 첫 push 및 Windows/Linux CI 실행.

## 2 법률 품질

- [ ] 변호사가 검토한 사건별 정답·관련 조문·찬반 판례 벤치마크 구축.
- [ ] 의미적 지지/모순 여부 평가와 모델 근거 검사 강화. 현재 텍스트 일치만 자동 검증.
- [ ] 시행일 기준 과거 법령 조회, 부칙·경과규정의 적용 검토.
- [ ] 후속 판례 인용 관계 및 판례 변경·폐기·구별 처리. 현재 사건 메타데이터 일치만 제공.
- [ ] 명시적 여러 쟁점 계획과 반복 재검색. 현재 계획은 법률명·검색어·상한을 정하는 규칙 기반.

## 3 실행과 자료 확장

- [ ] 지속 실행 작업 큐, 취소·재개·부분 재시도. 현재 단계별 저장만 지원.
- [ ] 지속 벡터 인덱스·증분 임베딩·재순위화 모델·캐시 TTL.
- [ ] 전체 판례 범위 확장과 데이터별 이용권한/이용조건 관리.
- [ ] 스캔 PDF OCR, HWPX 입력·출력, PDF 보고서, 검토서 편집 UI.
- [ ] 실제 ego/MCP 양방향 연결과 탐색 결과 검증·수입.
- [ ] 다중 사용자 인증·접근 통제·보관기간 정책. 현재 로컬 1인용 유지.

사용자의 API 인증값이나 실제 PC 연결 없이 확인할 수 없는 항목은 완료로 처리하지 않았습니다.
