# Korean Legal Research Studio

한국 법령·판례의 공식 원문을 검색하고, 설치된 로컬 Ollama 모델로 근거와 반론을 정리하는 **1인 로컬 법률 리서치 도구**입니다. 조사 결과를 MD·DOCX·JSON으로 내보내 동료가 검토하는 흐름을 지원합니다.

- 버전: v0.2 개발판 / 문서 기준일: 2026-11-11 (한국 시간)
- 실행 환경: Windows, Python, Streamlit, SQLite, Ollama
- 선택적 연동: 로컬 FastAPI 서버, Ollama 임베딩, ego 탐색 요청
- 상세 구현 기준: [개발명세서](docs/DEVELOPMENT_SPEC.md)

**완료 표시와 인용 일치는 법률 판단의 정확성을 보증하지 않습니다.** 현재 용도는 공식 원문 수집과 사람이 검토할 초안 작성입니다. 사건 적용, 과거 시행법, 판례 변경·폐기 여부는 사람이 확인해야 합니다.

## 1. 무엇에 사용하는가

| 업무 | 앱의 역할 | 사람이 해야 하는 일 |
|---|---|---|
| 사건 초기 조사 | 관련 법령·판례 검색, 본문 수집, 인용 대조 | 조사 쟁점과 사실관계 확정 |
| 검토서 초안 | 근거·반론 후보·출처·누락 사항 정리 | 법리 적용 및 결론 검토 |
| 계약 분쟁 조사 | 업로드 문서 발췌와 별도의 공식 자료 검색 | 계약 사실과 판례의 관계 연결 |
| 후배 조사 검토 | 조회 자료·검색어·단계 내역이 포함된 보고서 출력 | 인용 문맥과 사실관계 차이 검토 |

여러 사용자의 로그인·공동 편집·앱 내 승인 기능은 없습니다. 조사 담당자가 개인 PC에서 조사한 뒤 Word나 Markdown 보고서를 공유하는 방식입니다.

## 2. 가장 빠른 실행

1. 프로젝트 폴더의 **`Legal-Research-Studio.bat`**을 더블클릭합니다.
2. 서버가 준비되면 기본 브라우저에서 [앱 화면](http://127.0.0.1:8514)이 열립니다.
3. 실행 창은 사용 중 열어 두고, 종료할 때 `Ctrl+C`를 누릅니다.

번호 선택 메뉴는 없습니다. 같은 포트에 앱이 이미 실행 중이면 기존 화면을 엽니다. 일반 실행은 Streamlit 앱만 시작하며, Ollama나 REST API 서버까지 자동 실행하지는 않습니다.

### 처음 설치하는 PC

- Python 3.11 이상이 필요합니다. 이 PC에서는 Windows / Python 3.14.4 실행과 테스트를 확인했습니다.
- `.venv`가 없으면 BAT가 `py -3`으로 가상환경을 만들고 `requirements.txt`를 설치합니다.
- 가상환경은 있지만 패키지가 누락됐으면 다음 명령으로 복구합니다.

```powershell
.\Legal-Research-Studio.bat setup
```

설치에는 인터넷이 필요합니다. Ollama는 별도로 설치하고 실행해야 합니다. `.env`가 없으면 `.env.example`을 복사해 생성하며, 기존 `.env`는 덮어쓰지 않습니다.

### 실행 명령 전체

프로젝트 폴더의 PowerShell에서 실행합니다.

| 명령 | 동작 |
|---|---|
| `.\Legal-Research-Studio.bat` | 앱 실행, 준비 확인 후 브라우저 열기 |
| `.\Legal-Research-Studio.bat setup` | 현재 가상환경에 의존성 설치·복구 |
| `.\Legal-Research-Studio.bat verify` | 공식 API와 자동 선택 모델의 실제 연결 점검 |
| `.\Legal-Research-Studio.bat test` | pytest 실행 |
| `.\Legal-Research-Studio.bat demo` | 가상 데이터 모드, AI 비활성 상태로 앱 실행 |
| `.\Legal-Research-Studio.bat api` | 선택적 REST API 서버 실행, 포트 8800 |

데모와 실자료 모드를 바꾸려면 화면의 가상 샘플 모드를 사용하거나, 기존 서버를 종료한 뒤 원하는 명령으로 실행하세요. 서버가 이미 실행 중이면 `demo` 명령도 기존 화면을 엽니다.

## 3. 환경변수 설정

설정 파일은 **프로젝트 최상위의 `.env`**입니다. Windows 탐색기에서 확장자를 표시해 `.env.txt`로 저장되지 않았는지 확인하세요.

```dotenv
LAW_OC=
OLLAMA_BASE_URL=http://127.0.0.1:11434
OLLAMA_MODEL=
OLLAMA_EMBED_MODEL=
ENABLE_LLM=1
DEMO_MODE=0
DB_PATH=data/legal_studio.sqlite3
CACHE_SOURCE_DOCUMENTS=1
ALLOW_REMOTE_OLLAMA=0
```

| 항목 | 설정 방법과 의미 |
|---|---|
| `LAW_OC` | 국가법령정보 공동활용에서 발급받은 인증값. 실제 법령·판례 요청에 필요 |
| `OLLAMA_BASE_URL` | Ollama 서버 주소. 기본 로컬 포트 11434 |
| `OLLAMA_MODEL` | 선택 사항. 설치된 채팅 모델의 기본 선호값. 비우면 자동 선택 |
| `OLLAMA_EMBED_MODEL` | 선택 사항. 설치된 임베딩 모델의 기본 선호값. 비우면 자동 선택 |
| `ENABLE_LLM` | UI의 AI 분석 기본 활성값. REST 조사 요청은 `enable_llm`을 별도로 지정 |
| `DEMO_MODE` | `1`이면 가상 자료, `0`이면 공식 API |
| `DB_PATH` | SQLite 저장 위치. 상대 경로는 프로젝트 폴더 기준 |
| `CACHE_SOURCE_DOCUMENTS` | `1`이면 원문 캐시와 작업별 원문 스냅샷 저장 |
| `ALLOW_REMOTE_OLLAMA` | 기본 `0`. 원격 Ollama 서버를 사용할 때만 `1` |

환경변수를 이미 운영체제나 실행 창에 설정했다면 그 값이 `.env`보다 우선합니다. `.env` 수정 후에는 앱을 종료하고 다시 실행하세요.

인증값은 채팅·보고서·공개 저장소에 넣지 않습니다. `.env`는 `.gitignore` 대상입니다. API 이용 신청은 [국가법령정보 공동활용](https://open.law.go.kr/)에서 진행합니다.

## 4. Ollama 모델 선택

모델명은 코드에 고정하지 않습니다. 앱이 `/api/tags`로 설치 모델을 조회하고 `/api/show`의 기능 정보를 사용합니다.

- `completion` 기능이 있는 모델: 채팅 목록에 표시
- `embedding` 기능이 있는 모델: 임베딩 목록에 표시
- 설치된 기본 선호 모델이 있으면 우선 사용
- 선호값이 없거나 유효하지 않으면 설치 용량이 가장 작은 해당 기능 모델을 기본 선택
- 같은 용량은 이름 순으로 정렬. 이 기준은 법률 정확도 순위가 아닙니다.

사이드바에서 **Ollama 모델**, **임베딩 모델**, **AI 분석 활성화**를 설정합니다. 새 모델을 설치한 뒤에는 **설치된 모델 새로고침**을 누르세요. 목록은 최대 30초 캐시합니다.

```powershell
ollama list
ollama ps
```

`list`는 설치 모델, `ps`는 현재 메모리에 올라간 모델 확인용입니다. 모델을 선택하는 것만으로 조사가 시작되지는 않습니다. 임베딩 모델이 없으면 키워드 검색을 사용하고, 임베딩 호출 실패 시에도 키워드 순위로 돌아갑니다. 채팅 모델이 없으면 AI 없이 검색·원문 대조를 사용할 수 있습니다.

## 5. 실행 후 실제 연결 확인

**설정·로그 → 전체 연결 점검**을 누릅니다. 앱의 전체 탭이 보이지 않으면 탭 오른쪽 화살표로 이동하세요.

| 점검 항목 | 성공 조건 |
|---|---|
| 법령 검색·조문 | 민법 완전 일치 검색과 조문 본문 수신 |
| 판례 검색·본문 | 채권양도 검색 결과의 판결 본문 수신 |
| 채팅 모델 | 점검용 가상 자료에 대한 JSON 응답과 인용 문구 대조 성공 |
| 임베딩 모델 | 점검 문서의 유효 벡터 수신 |

각 결과를 독립적으로 표시합니다. 하나가 실패해도 다음 항목을 점검합니다. `미설정`은 인증값·모델 선택 등이 없다는 뜻이며, 점검 실패와 구분합니다. 마지막 점검 결과는 현재 브라우저 세션에 표시되므로 모델을 바꿨다면 다시 점검하세요.

이 검사는 실제 요청과 추론을 수행합니다. CPU 환경에서는 시간이 걸릴 수 있습니다. 연결 성공은 법률 정확도, 장시간 안정성, 검색 품질의 합격 판정이 아닙니다.

CLI의 `verify`는 별도 진단 형식입니다. 설정 여부와 선택 모델을 JSON으로 출력하며, UI의 인용 대조 점검보다 검사 범위가 좁습니다.

## 6. 화면별 사용법

### 법령·조문

1. 가능한 한 정확한 법령명으로 검색합니다.
2. 법령명과 시행일을 확인하고 **전체 조문 열기**를 누릅니다.
3. 조문번호·제목·내용을 검색하고 부칙을 확인합니다.
4. AI를 켰다면 선택 조항의 원문 기반 해설을 요청할 수 있습니다.

API 후보 최대 100건을 받은 후 공백을 제외한 법령명 완전 일치를 먼저 배치합니다. 그다음 이름 시작 일치와 이름 순으로 정렬하고 요청 건수로 자릅니다. API 첫 100건 밖의 자료까지 완전 검색했다는 보장은 없습니다. 표시된 시행일이 사건 발생일의 적용법이라는 뜻도 아닙니다.

### 판례 리서치

짧은 핵심어로 검색한 뒤 원문을 불러옵니다. 유사 판례 순위, 두 판례 비교, 판결문 구조 분석, 사건번호·법원·선고일 대조를 사용할 수 있습니다.

자동 분석용 검색은 **법제처 API의 대법원 제공 데이터(`datSrcNm=대법원`)**를 사용합니다. 이는 대법원 판결만이라는 의미가 아니라 API 데이터 제공기관 조건입니다. 국세청 HTML 전용 자료는 이 검색에서 제외됩니다. 전체 국내 판례를 망라하지 않습니다.

유사도 점수는 검색한 후보 내 순위입니다. 승소 가능성이나 법리 지지 확률이 아닙니다. 반대 판례 후보 역시 검색어로 찾은 후보이며, 법리 충돌 확정 결과가 아닙니다.

### 심층 리서치

질문, 법률명, 판례 검색어, 검토할 주장, 기준일을 입력합니다. 조사 깊이는 다음과 같습니다.

- `quick`: 기본 조사, 반론 검색 생략, AI 분석 최대 1회
- `research`: 기본 조사와 선택적 반론 검색, AI 분석·반론·검토 최대 3회
- `deep`: 여러 단어로 된 검색어의 첫 단어를 추가 검색어로 사용. 자율 재계획 기능은 아님

UI의 기본 판례 본문 설정은 최대 8건입니다. 내부 기본 수집 상한은 12건, 반론은 추가 최대 3건입니다. 여러 검색 결과를 교차 수집하며, 기본 조사와 반론 조사에서 같은 본문을 다시 요청할 수 있습니다.

단계 진행률, 경과 시간, 원문 수, 마지막 저장 시각을 표시합니다. 진행률은 단계 배정값이며 남은 시간 예측값이 아닙니다. 긴 API·모델 호출 중에는 다음 저장 지점까지 숫자가 바뀌지 않을 수 있습니다.

### 문서 분석

PDF·DOCX·TXT·Markdown을 업로드해 텍스트 추출, 판결문 구조 추출, 직접 인용 대조, 선택적 AI 분석을 합니다.

- 파일 최대 12MiB, 추출 텍스트 최대 130,000자
- PDF 최대 80쪽, 암호화 PDF·스캔 OCR 미지원
- DOCX 표는 텍스트로 추출하며 원래 배치·각주·머리말은 완전히 보존하지 않음
- TXT·MD는 UTF-8 BOM 포함 및 CP949 읽기 지원
- 업로드 자료는 `USER_UPLOAD`로 취급하며 공식 법적 권위 자료로 자동 승격하지 않음

### 기록·보고서

저장된 작업의 마지막 단계, 진행률, 원문 목록과 역할별 기록을 확인합니다. MD·DOCX 보고서를 내보낼 수 있고, 현재 조사 화면에서는 JSON도 내려받을 수 있습니다.

조사가 중단되면 마지막 저장본이 남을 수 있습니다. 조회 기능이며 자동 재개·취소·실패 단계 재시도는 아직 없습니다. 완료 전 보고서는 완료본과 구분해 사용하세요.

### 웹 탐색 보조

허용된 공식 사이트 URL과 쟁점으로 탐색 요청 JSON·프롬프트를 만듭니다. 로컬 ego 가이드 확인도 제공합니다. 앱이 브라우저를 자동 조작하거나 탐색 결과를 자동 수입하는 기능은 없습니다.

## 7. 실제 협업 예시

**채권양도 사건 초기 조사:** 변호사가 쟁점을 정하고 조사 담당자가 민법·관련 판례를 검색합니다. 앱으로 근거와 반론 후보를 정리한 뒤 DOCX를 공유합니다. 변호사는 원문 링크, 인용 문맥, 통지 관련 사실과 증거를 확인하고 의견을 확정합니다.

**계약 해지 분쟁 검토:** 사업팀은 계약서와 사실관계를 전달합니다. 법무 담당자는 문서 분석으로 조항을 읽고 별도로 관련 판례를 조사합니다. 계약 내용과 판례의 관계 연결, 상대방 주장 평가, 최종 대응은 사람이 수행합니다.

**선임의 조사 검수:** 후배가 질문·검색어·검토 주장과 함께 조사를 저장합니다. 선임은 보고서의 자료 목록·제외 인용·반론 후보를 읽고 추가 조사 사항을 문서 댓글로 전달합니다. 앱 내 공동 편집·승인 기능은 없습니다.

## 8. 저장과 데이터 취급

기본 DB는 `data/legal_studio.sqlite3`입니다.

| 저장 항목 | 내용 |
|---|---|
| 원문 캐시 | 법령·판례 정규화 본문, 메타데이터, 해시 |
| 조사 작업 | 질문·요청 조건·결과·현재 단계·진행률·경과 시간 |
| 실행 로그 | 역할·상태·오류 유형 등의 기록 |
| 원문 스냅샷 | 해당 작업에서 사용한 원문과 당시 메타데이터 |

단계 경계와 판례 원문 수신 시 중간 저장합니다. 스냅샷은 작업별 원문 ID 기준으로 최초 저장 후 덮어쓰지 않습니다. 해시는 원시 XML 파일이 아닌 분석용 정규화 본문 기준입니다.

`CACHE_SOURCE_DOCUMENTS=0`이어도 작업 질문·인용·발췌·분석 결과는 저장됩니다. 완전 무기록 모드가 아닙니다. 업로드 원본 파일은 기본 추출 과정에서 DB에 저장하지 않습니다.

백업은 앱과 API 서버를 종료한 뒤 `.env`와 `data/`를 함께 복사합니다. 설정·로그의 전체 삭제는 현재 로컬 DB 데이터를 지우며 외부 백업을 지우지는 않습니다.

## 9. 상태 표시 읽기

| 표시 | 의미 |
|---|---|
| `PLANNING` / `RETRIEVING` / `ANALYZING` / `VERIFYING` | 마지막 저장 시점의 조사 단계 |
| `COMPLETED` | 요청 흐름 완료. 법률 검토 완료를 뜻하지 않음 |
| `PARTIAL` | 경고·원문 부족·일부 누락 등이 있는 완료 결과 |
| `FAILED` | 조사 전체 처리 중 예외 발생. 일부 저장 자료가 있을 수 있음 |
| `SKIPPED` | 해당 역할을 실행하지 않음 |
| `QUOTE_MATCH_ONLY` | 원문에 인용 문구가 있는지 대조 |
| `METADATA_MATCH_ONLY` | 사건 정보 필드 대조 |
| `CANDIDATE_NOT_CONFIRMED` | 반론 검색 후보, 법리 충돌 미확정 |

보고서의 사람 검토 표시는 현재 기본 `미검토` 기록입니다. 이를 변경하는 앱 내 승인 절차는 아직 없습니다.

## 10. 자주 생기는 문제

| 증상 | 확인·조치 |
|---|---|
| 브라우저가 안 열림 | 실행 창 오류 확인 후 http://127.0.0.1:8514 직접 열기 |
| 모델 목록이 비어 있음 | Ollama 실행, `ollama list`, 로컬 주소, 모델 새로고침 확인 |
| 임베딩 미설정 | 검색은 사용 가능. 의미 검색이 필요할 때 임베딩 기능 모델 설치·선택 |
| API 인증 설정됨인데 검색 실패 | 실제 연결 점검으로 인증·서비스 권한·응답 상태 확인 |
| 판례 목록은 있으나 본문 없음 | 원문 제공 범위 확인. HTML 전용·미제공 자료를 XML 본문으로 처리하지 않음 |
| 모델 응답이 느림 | `ollama ps`로 실행 모델 확인. 작은 설치 모델, quick 모드, 적은 판례 수 사용 |
| AI JSON·인용 오류 | 점검 결과 확인. 오류 출력은 검증된 주장으로 채택하지 않음 |
| 중단된 조사 | 기록·보고서의 마지막 저장본 조회. 자동 이어하기는 미지원 |
| 코드 수정 후 새 필드 오류 | 실행 창에서 Ctrl+C 후 BAT로 서버 재시작. 새로고침만으로 모듈 교체가 안 될 수 있음 |
| 패키지 없음 | BAT `setup` 실행 |
| 포트 사용 중 | 기존 앱을 닫거나 기존 서버 화면 사용. 포트 점유만으로 다른 앱을 종료하지 말 것 |

## 11. 검증 현황과 한계

2026-11-11 현재 세션에서 확인한 결과입니다. 모델·API 응답과 검색 수치는 조회 시점에 따라 달라집니다.

- Windows / Python 3.14.4에서 자동 테스트 **63개 통과**
- 실제 민법 검색·조문 1,193개 수신
- 실제 판례 검색·본문 수신 및 조회 오류 수정 확인
- 설치 모델 자동 선택, 채팅 JSON·점검용 인용 대조 성공
- 브라우저에서 실행 화면과 설정·로그 점검 항목 확인
- 임베딩은 모의 프로토콜·대체 처리 테스트만 수행. 현재 PC에 설치된 임베딩 모델이 없어 실모델 검증 미완료
- 법률 전문가 정답셋, precision/recall, 법적 함의 검증, 모델별 정확도·속도 비교는 미수행
- GitHub Actions 설정은 존재하나 이 문서가 CI 실제 실행 성공을 보증하지 않음

정확도 평가 없이 승소 가능성, 법률 결론의 신뢰율, 상용 플랫폼과의 동등성을 수치로 제시하지 않습니다. 후속 판례·변경·폐기, 역사적 시행법 자동 선택, OCR/HWP/HWPX, 지속 벡터 DB, 사용자 인증·권한·보존정책, 작업 큐는 미구현입니다.

선택적 REST API를 켠 뒤 [Swagger 문서](http://127.0.0.1:8800/docs)를 사용할 수 있습니다. UI 모드와 모델 선택은 별도로 실행한 API 서버에 자동 전달되지 않습니다.

`requirements.txt`는 허용 버전 범위이고, `requirements-tested.txt`는 과거 Linux 검증 당시 직접 의존성 버전 목록입니다. 모든 환경을 재현하는 전체 의존성 잠금 파일은 아닙니다.

이 앱은 localhost 기반의 인증 없는 개인용 도구입니다. 외부 공개 운영을 위해서는 별도 인증·권한·비밀 관리·보존정책 설계가 필요합니다.
